# Workspace Fix Notes — 2026-04-15

This revision applies direct fixes across the full workspace, focused on the API verification issues seen during local testing.

## Service API
- Added role-scoped session cookies in `services/api/src/modules/auth/auth.routes.ts`
  - `cc_provider_access_token`, `cc_provider_role`
  - `cc_admin_access_token`, `cc_admin_role`
  - `cc_patient_access_token`, `cc_patient_role`
- Updated refresh handling so scoped cookies are rewritten on token refresh.
- Expanded logout to clear scoped cookies as well as legacy generic cookies.
- Relaxed `/api/appointments/booking-policy-preview` so `providerId` is no longer mandatory when the preview can still be evaluated.
- Expanded provider calendar route access for privileged admin/support roles and added provider-scope resolution via `providerId` or first org provider fallback.
- Expanded provider prescription route access for privileged admin/support roles.
- Optimized patient medical-record fetching to reduce query weight.
- Optimized patient dashboard appointment query to reduce payload size and DB pressure.

## Web portals
- Added scoped cookie usage to reduce cross-portal session collisions between Admin and Provider web apps.
- Provider web now prefers `cc_provider_access_token` / `cc_provider_role`.
- Admin web now prefers `cc_admin_access_token` / `cc_admin_role`.
- Fallback to legacy `cc_access_token` / `cc_role` remains for compatibility.

## Preserved custom changes
- Patient mobile `apps/mobile/lib/features/booking/presentation/screens/select_slot_page.dart` remains preserved from the manual user replacement in earlier revisions.
