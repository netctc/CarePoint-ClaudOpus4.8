# CarePoint Phase 4 - Controlled Pilot / Go-Live Execution Roadmap

## Recommended delivery count

Phase 4 should be completed in **6 deliveries**.

| Delivery | Focus | Closure intent |
|---|---|---|
| PILOT-V1 | Pilot execution charter, scope, gates, and cohort plan | Establish controlled execution governance before any launch activity. |
| PILOT-V2 | Staging deployment rehearsal and environment activation | Prove the target environment can run the release path safely. |
| PILOT-V3 | Controlled pilot launch runbook and day-0/day-1 execution | Execute the first controlled launch window. |
| PILOT-V4 | Pilot monitoring, support, incident triage, and daily health review | Stabilize real usage under operational observation. |
| PILOT-V5 | Pilot feedback, defect burn-down, adoption evidence, and expansion decision | Decide whether the product can expand beyond the initial cohort. |
| PILOT-V6 | Final go-live execution certificate and phase closure | Close controlled pilot/go-live execution or define a corrective release. |

## Boundary

This phase starts after:

- Option B Python Progressive closed at V64.
- Design Refinement and UX Stabilization closed at UX-V6.
- End-to-End QA, UAT and Production Readiness closed at QA-V7.

Phase 4 should not re-open those phases unless a critical defect is discovered. New work should be managed as pilot execution evidence, release operations, pilot feedback, or controlled go-live decision records.

## Success definition

The phase is successful when CarePoint has either:

1. completed a controlled pilot with accepted evidence and an approved production expansion decision, or
2. completed a controlled go-live with rollback readiness, support readiness, and release-owner signoff.
