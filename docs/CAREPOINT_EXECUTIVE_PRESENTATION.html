Verified → JWT issued ━━━━━━━━━━━━━━━━━━━━━━━━━━━━ Privileged MFA Flow: ━━━━━━━━━━━━━━━━━━━━━━━━━━━━ 1. Admin/Provider logs in 2. MFA challenge issued 3. Code via TOTP/SMS/Email 4. User verifies challenge 5. Full session granted ━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Database Architecture

Core Entity Relationships

Organization (Multi-Tenant Root) ├── User (9 roles) │ ├── PatientProfile │ │ ├── Appointments │ │ ├── MedicalRecords │ │ ├── Payments │ │ ├── MessageThreads │ │ └── FamilyProfiles │ └── ProviderProfile │ ├── Appointments │ ├── CredentialDocuments │ ├── OnboardingState │ └── ScheduleTemplates ├── TelehealthSession ├── ClinicalOrder ├── PrescriptionDraft ├── LabWorkItem ├── RpmEnrollment ├── ServiceCatalog ├── CoverageRule ├── PricingRule ├── AuditLog └── RefreshToken

Key Design Patterns

  • Multi-tenancy: All tables scoped to Organization
  • Soft deletes: Status fields vs hard delete
  • JSON flexibility: Metadata/data columns for evolving schemas
  • Strategic indexes: (orgId, status, date) patterns
  • Enum constraints: DB-level validation
